## 1. 概念

### 1.1 AOP

- **是什么：** 面向切面编程：把横切逻辑（日志、鉴权、计时）从业务方法抽离。
- **为什么需要：** 每个 Controller 手写日志会复制粘贴且易漏。
- **怎么做：** 定义 Aspect，在 Join Point 织入 Advice。
- **代码：** `ApiLogAspect`
- **坑：** 切面逻辑过重会拖慢所有 API。

### 1.2 Proxy

- **是什么：** Spring AOP 默认通过代理调用目标方法（接口→JDK Proxy；类→CGLIB）。
- **为什么需要：** 不改业务源码即可插入前后逻辑。
- **怎么做：** 引入 `spring-boot-starter-aop`，容器为 Bean 创建代理。
- **代码：** 调用 `TaskApiController` 时实际先经过代理再进 `getTask`
- **坑：** **自调用不经过代理**（同类 `this.foo()` 切不到）。

#### 重学深挖：两种代理对比

| 代理方式 | 原理 | 条件 | 局限 |
|---|---|---|---|
| JDK 动态代理 | `Proxy.newProxyInstance`，基于接口 | 目标类必须实现接口 | 只能代理接口方法 |
| CGLIB | `Enhancer` 生成字节码子类 | 目标类不需要接口 | 无法代理 `final` 类/方法 |

Spring Boot 2.x 起默认强制 CGLIB（`spring.aop.proxy-target-class=true`），避免「接口有方法但实现类是代理」的混乱。

#### 重学深挖：调用链与自调用失效

```text
HTTP 请求
    ↓
DispatcherServlet
    ↓
Proxy（切面壳）   ← 只有经过这层，AOP 才生效
    ↓
@Around 前置逻辑
    ↓
proceed() → 真实 TaskApiController.getTask()
    ↓
@Around 后置逻辑
```

自调用 `this.getTask()` 直接走真实对象，不经过 Proxy，因此切面失效。解法：拆 Service 或注入自身代理。

### 1.3 Pointcut

- **是什么：** 哪些方法要被切中的匹配表达式。
- **为什么需要：** 精确控制织入范围，避免切到仓储/工具类。
- **怎么做：** `execution(public * com.example.day9.web..*(..))`
- **代码：** `ApiLogAspect#apiMethods`
- **坑：** 表达式写错 → 切面「没生效」却无编译错误。

### 1.4 Advice

- **是什么：** 在匹配点执行的动作：Before/After/Around/AfterThrowing 等。
- **为什么需要：** Around 可统一计时并在异常路径打日志。
- **怎么做：** `@Around` 里 `proceed()`，catch 后记录再抛出。
- **代码：** `ApiLogAspect#logApi`
- **坑：** catch 后吞掉异常会导致业务误以为成功。

### 1.5 Aspect

- **是什么：** Pointcut + Advice 的模块化单元；类上 `@Aspect` + `@Component`。
- **为什么需要：** 日志切面可复用到所有 web 方法。
- **怎么做：** 见 `ApiLogAspect`
- **坑：** 忘记 `@Component` → Aspect 不会成为 Bean → 不织入。

## 4. 自测

1. AOP 和 OOP 解决的问题有何不同？
2. 为什么需要 Proxy？不用代理直接改源码怎样？
3. `pjp.proceed()` 这一行在做什么？

### 参考答案

1. OOP 按对象封装；AOP 按横切关注点封装。
2. 代理让框架在调用链插入逻辑；硬改源码则横切与业务耦合。
3. 调用目标方法；返回值/异常从这里出来，便于前后环绕。

### 2026-09-11 重学标准答案

#### 第 1 问：为什么 Spring AOP 要通过代理对象调用目标方法，而不是直接改字节码插桩？

**答：**
Spring AOP 选择代理模式而非字节码插桩（如 AspectJ 编译时织入），核心原因是**简单、安全、够用**：

1. **与 IoC 容器无缝集成**：代理对象本身就是 Bean，天然受容器管理，无需额外编译步骤；
2. **运行时决策**：切点表达式可以在启动后根据配置动态匹配，改字节码则必须编译期或类加载期确定；
3. **避免破坏封装**：不修改目标类字节码，调试栈、异常堆栈更清晰；
4. **性能够用**：Spring AOP 针对的是「方法调用级别」的拦截，代理反射开销在业务场景可接受；真正需要字段级、构造器级织入时才上 AspectJ。

代价就是：**只能拦截「从容器外部调用 Bean 方法」的场景**，同类 `this.foo()` 自调用、final 方法、private 方法都切不到。

#### 第 2 问：什么情况下 `@Around` 里 `pjp.proceed()` 会抛异常？catch 后必须做什么？

**答：**
`pjp.proceed()` 会抛出目标方法执行时抛出的**任何异常**（受检或非受检）。例如 `taskService.get(id)` 里抛 `TaskNotFoundException`，或更底层的 `NullPointerException`，都会从 `proceed()` 处抛出。

catch 后**必须重新抛出**（原样或包装后）：

```java
@Around("apiMethods()")
public Object logApi(ProceedingJoinPoint pjp) throws Throwable {
    try {
        return pjp.proceed();
    } catch (Exception e) {
        log.error("API 异常", e);
        throw e;  // 必须抛！否则上层以为成功，事务不会回滚，监控收不到告警
    }
}
```

吞掉异常会导致：
- 调用方拿到 `null` 或错误结果；
- Spring 事务认为方法正常提交；
- 全局异常处理器（`@ControllerAdvice`）捕获不到。

#### 第 3 问：为什么同类内部调用 `this.getTask()` 不会触发切面？如果想触发，怎么做？

**答：**
因为 `this` 指向的是**目标对象本身**，不是 Spring 生成的代理对象。AOP 织入发生在代理壳上，`this.getTask()` 直接走真实对象，绕过了代理，自然没有日志、事务、权限等增强。

解法（按推荐度排序）：

1. **拆方法到别的 Bean**（最佳）：把 `getTask` 挪到 `TaskService`，Controller 注入 Service 调用；
2. **注入自身代理**：
   ```java
   @Autowired
   private TaskApiController self;  // 注入的是代理对象

   public Task self() {
       return self.getTask(1L);  // 走代理，AOP 生效
   }
   ```
3. **暴露代理**：`AopContext.currentProxy()`，需开 `@EnableAspectJAutoProxy(exposeProxy = true)`，代码侵入大，少用。

五问结论：学了代理织入；为了横切复用；不用则日志散落；坑是自调用与吞异常。
