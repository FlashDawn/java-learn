## 一、理论笔记：JDK / JVM / JRE 与编译

### 1. 概念

Java 源码不能直接双击运行，开发与运行拆成三层：

| 名称 | 含义 |
|---|---|
| JDK（Java Development Kit） | 开发工具包：JRE + `javac` + 调试等工具。写代码必须装 JDK。 |
| JRE（Java Runtime Environment） | 运行环境：JVM + 核心类库。只能运行已经编译好的程序。 |
| JVM（Java Virtual Machine） | 虚拟机：执行 `.class` 字节码的那一层。 |

从属关系（从内到外）：

```text
JVM ⊂ JRE ⊂ JDK
```

两个文件角色：

- `.java`：给人看的源码
- `.class`：给 JVM 看的字节码，由 `javac`（或 Maven 的 compile）生成

### 2. 为什么需要它

- 没有 JVM：无法「一次编写、到处运行」，要为每个操作系统单独生成机器码。
- 没有 JRE：机器上没有执行引擎和类库，`.class` 只是文件。
- 没有 JDK：编不出 `.class`，只能当使用者，不能当开发者。

后端服务最终都是「一份字节码 + 一台 JVM」。

### 3. 工作原理

```text
TaskApp.java     javac      TaskApp.class      java       JVM 执行
  （源码）    ────────→    （字节码）     ────────→   打印结果
```

- `javac`：只编译，不执行业务逻辑。
- `java <主类名>`（不带 `.java`）：启动 JVM → 加载已有 `.class` → 找 `main` → 执行字节码。
- `public class` 名必须和文件名一致。

**JDK 版本差异（学员补充，当日不细究）：**

| 版本 | 日常怎么跑单个文件 |
|---|---|
| JDK 8 及更早 | 必须先 `javac TaskApp.java`，再 `java TaskApp`。只改源码不重新编译，`java` 看到的是旧 `.class`。 |
| JDK 11 及以后（含本机 JDK 21） | 可以直接 `java TaskApp.java`，由 `java` 命令顺带完成编译再运行，因此不先 `javac` 也能看到修改后的输出。 |

多文件工程、Maven、生产环境仍以显式编译为准（`javac` / `mvn compile` / `mvn package`），不要把单文件快捷方式推广成后端构建方式。

JIT、G1 等细节放到第 8 周。

### 5. Spring Boot 中会怎么用（第 1 周只记结论）

Spring Boot 本质仍是 `.java` → `.class` → JVM 跑 `main`。Maven 把编译、拷依赖、打 jar 自动化。生产常见：

```text
mvn -DskipTests package
java -jar task-service.jar
```

`java -jar` 仍然是启动 JVM。细节第 2 周再学。

### 6. 常见错误

- 只装 JRE 没有 JDK：有 `java` 没有 `javac`
- 改了 `.java` 忘了重新 `javac`：JDK 8 上跑旧字节码；JDK 11+ 用 `java 源文件.java` 则可能是新结果
- `public class` 名和文件名不一致
- 写成 `java TaskApp.class`（应写类名，不要带 `.class`）
- `JAVA_HOME` / IDE / 终端不是同一份 JDK

### 7. 生产环境注意事项

- 运行环境版本 ≥ 编译版本
- 服务器通常只 `java -jar`，不在生产机上 `javac`
- 不要混用发行版和版本；出问题先看 `java -version`
- 源码含中文统一 UTF-8
- 版本库提交源码和 `pom.xml`，不提交 `target/`、`.class`

## 二、闸门三问（理论块）

### 第 1 问：JDK / JRE / JVM 是什么？谁包含谁？

**学员回答：** JDK 是完整开发工具包（运行环境、编译器、调试工具）；JRE 仅能执行 Java 程序；JVM 是执行 class 的层。从内到外：JVM、JRE、JDK。

**评语：通过。** JVM 记成「执行 `.class` 的虚拟机」即可，不必说「中台/解码」。

### 第 2 问：为什么必须装 JDK？

**学员回答：** JDK 包含运行环境以及编译、调试等开发工具，并非只有运行环境。

**评语：通过。** 补充：只有 JRE 时能跑别人编好的程序，但没有 `javac`，自己的 `.java` 编不成 `.class`。

### 第 3 问：`javac` 和 `java` 各自做什么？

**学员回答：** `javac` 生成 class；`java` 会编译并执行；不重新 javac 时 class 不变，但 java 仍能看到修改后结果。

**初评按 JDK 8 判未通过，有误。** 学员指出这是版本差异：JDK 8 必须先 javac 再 java；JDK 11+ 可直接 `java` 跑源文件。本机 JDK 21 现象成立。

**订正后评语：通过。** Maven / 生产不要依赖单文件快捷方式。

## 三、Maven 结对笔记

### 学员理解（进入结对时）

> Maven 是便于 Java 项目管理和协作开发的完整项目工具，而非简单的编译器。`pom.xml` 是描述项目基础信息的清单，揭示版本、依赖和配置。`src/main/java` 是主要代码目录，主类放在这里作为入口。`mvn clean package` 会经历 clean、resources、compile、testResources、testCompile、test 和 jar，产物在 `target`（class 和 jar）。失败可能由版本不一致、路径错误或未配置、环境配置错误造成，命令行会输出 BUILD FAILURE。

### 对照订正

| 点 | 结论 |
|---|---|
| Maven 不是 javac 马甲 | 对。它是项目模型 + 依赖 + 约定目录 + 构建生命周期 + 插件。 |
| 协作 | 协作主要靠 **Git**。Maven 保证「拉下来用同一套依赖和同一条构建命令能编过」。 |
| `pom.xml` | 对。核心是坐标（`groupId` / `artifactId` / `version`）、依赖、插件、编码与 JDK 版本。 |
| 主类 | 入口是带 `main` 的类，不是「放在 src/main/java 根上就叫入口」。`java -jar` 还要在 pom 里声明 `mainClass`。 |
| 生命周期 | 顺序理解对。官方阶段名是 `process-resources`、`test-compile`、`process-test-resources`、**`package`**。`jar` 是 package 阶段里 jar 插件做的事，不是阶段名本身。 |
| 失败排查 | 对：版本、路径、环境；日志看 `BUILD FAILURE`。另：测试失败时默认不会打出 jar；缺 `mainClass` 时 `java -jar` 报 no main manifest attribute。 |
