## 1. 概念

### 1.1 Exception（受检）与 try/catch

- **是什么：** 继承 `Exception` 且非 Runtime 的异常，编译器要求处理或声明 `throws`。
- **为什么需要：** IO、网络等「调用方必须知道可能失败」的路径，避免默默忽略。
- **怎么做：** `throws TaskException` + `catch (TaskException e)`
- **代码：** `TaskException`；`Day5App.startOnlyWhenCreated`
- **坑：** 空的 `catch (Exception e) {}` 吞掉错误，生产排障无日志。
- **坑：** 把所有失败都做成受检异常，签名污染严重；业务可恢复用受检或结果类型，编程错误用运行时。

### 1.2 RuntimeException

- **是什么：** 非受检，不必在方法签名声明。
- **为什么需要：** 非法状态、空指针这类「代码写错了」不应强迫每个调用方声明 throws。
- **怎么做：** `throw new BadTaskStateException(...)`
- **代码：** `BadTaskStateException`；`requireCreated`
- **坑：** 滥用 Runtime 导致调用方完全不处理，故障飞到顶层。
- **坑：** 在库边界把受检异常粗暴包成 Runtime 却丢失 cause。

### 1.3 IO（本 Demo：文件读写）

- **是什么：** 与外部资源交互；失败通常是 `IOException`（受检）。
- **为什么需要：** 任务笔记、配置、导出文件都要读写磁盘。
- **怎么做：** `Files.writeString` / `readString`，用完删临时文件。
- **代码：** `Day5App` 的 `io=`
- **坑：** 忘关流（本 Demo 用 Files API 自动管理）；老式 `InputStream` 必须 try-with-resources。
- **坑：** Windows/Linux 编码不一致，固定 `UTF_8`。

### 1.4 Annotation

- **是什么：** 给代码加的元数据，可被编译器或运行时读取。
- **计划内三个：**
  - `@Override`：覆盖父类方法，签名错则编译失败（Day2 ImportTask 已用）。
  - `@Deprecated`：标记过时 API，调用方会收到警告。
  - `@SuppressWarnings`：压制警告（慎用，本 Demo 仅演示）。
- **自定义：** `@TaskHandler("import-orders")`，`RUNTIME` 保留才能反射读到。
- **代码：** `TaskHandler.java`、`ImportHandler.java`、`Day5App` 的 `suppress=`
- **坑：** 注解 `Retention` 若是 SOURCE/CLASS，运行时 `getAnnotation` 为 null。
- **坑：** 靠 `@SuppressWarnings("unchecked")` 掩盖泛型问题，而不是修类型。

### 1.5 Reflection（反射）

- **是什么：** 运行时根据 Class 对象读注解、造实例、调方法。
- **为什么需要：** 框架不知道你会写哪个 Handler，只能扫描注解再调用。
- **怎么做：** `ImportHandler.class.getAnnotation` → `getDeclaredConstructor().newInstance()` → `getMethod("handle").invoke`
- **代码：** `Day5App` 的 `ann=`、`handle=`
- **坑：** 反射绕过封装、性能差、缺编译期检查；业务代码少用，留给框架。
- **坑：** 模块系统/安全管理器下 `setAccessible` 可能失败。

### 1.6 Spring 为何大量依赖 Annotation + Reflection

Spring 扫描 `@Service`/`@Autowired` 等注解，用反射创建 Bean 并注入依赖。你写注解，容器在启动时「发现」类——这就是 IoC 的落地方式。第 2 周细讲；今天记住：**注解声明意图，反射在运行时执行意图。**

## 4. 自测

1. `TaskException` 和 `BadTaskStateException` 对调用方的编译要求有何不同？
2. 为什么自定义注解要 `@Retention(RUNTIME)`？
3. Spring 和本 Demo 的反射调用有何相同点？

### 参考答案

1. 受检必须 catch/throws；Runtime 不强制。
2. 否则运行时反射读不到注解。
3. 都是先读元数据再实例化/调用，业务类不直接 `new` 被框架管理的对象。
