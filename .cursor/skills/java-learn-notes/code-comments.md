# 教学代码注释规范

写 `dayN` 配套 Java 时必须遵守。目的：读者只看源码也能把「当日计划条目」对上「这段代码在证明什么」。

## 必须有的三层注释

1. **文件头（类/接口 Javadoc）**
   - 写明：Day N、钉死的概念名、与 `学习笔记.md` 哪一节对应（可写「对照笔记 §x」）
   - 一句话说明在综合项目里将来落哪个服务（若已知）

2. **分段注释（入口 `DayNApp` / `main`）**
   - 用 `// ========== 概念名：… ==========` 或等价分隔，把计划条目与代码块对齐
   - 每一段只服务 1～2 个概念，写清「为什么这样写」，禁止只复述代码字面意思

3. **关键符号旁注**
   - 字段/方法：封装点、状态机、锁、泛型参数、Stream 操作名等，用一行说明与当日主题的关系
   - 易错点（如 `start()` vs `run()`、Abort 后再 submit）必须在旁注明

## 写法要求

- 中文；专有名词保留英文（`HashMap`、`volatile`、`CompletableFuture`）
- 注释写「为什么 / 对照哪条学习内容」，不要写 `i++ // i 加一`
- 类名、方法名本身也要钉概念（`ImportTask extends Task`）；注释是补「和笔记的映射」，不是代替好命名
- 压缩多日时：每个 `dayN` 文件头只写该日主题，不要把 Day3 集合注释抄进 Day4

## 验收（Agent 自检）

落盘前问自己：

- [ ] 不打开笔记，能否从注释看出本日学了哪些计划条目？
- [ ] `DayNApp` 是否按条目分段？
- [ ] 笔记「代码导读」里的符号，在源码旁是否有对应说明？
