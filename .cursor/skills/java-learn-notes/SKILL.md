# Java 学习笔记与配套代码

聊天记录不是教材。每次学完（含压缩、跳项、多日合并）必须在磁盘留下**可独立阅读**的学习包。笔记规格见 [note-template.md](note-template.md)。

## 何时落盘

- 理论块结束时：先写/更新 `dayN/学习笔记.md` 和 Demo 代码，不要等收工
- 用户说整理笔记、结束今天、压缩、跳过某块、Day A 到 Day B
- 结对或补概念之后：立刻把新内容合并进笔记，并保证代码与笔记一致

## 学习包布局

```text
dayN/                          # 对应计划第 N 日；多日则多个 dayN
├── 学习笔记.md                 # 必选，当天唯一教材
├── README.md                  # 可选，仅当代码超过 3 个文件时写「如何运行」
└── ... 可运行源码
```

代码形态按阶段选择，不要为笔记再发明一套无关例子：

- 第 1 周前期：`dayN/*.java` 即可（JDK 21 可用 `java Xxx.java`）
- 已有 Maven：放进当天工程 `src/main/java`，笔记写清模块路径
- 领域模型固定用 `User` / `Task` / `Order`

多日压缩：每个计划日一个 `dayN/`，不要把 Day 2 和 Day 3 揉进同一个笔记文件。

跳过某一日：不在 `dayN/` 伪造「已学完」长文；在进度和最近一份笔记里写：

```text
⏭ 跳过 Day X（主题）：原因一句话；日后补时从计划第四章该日开始。
```

## 笔记质量（硬标准）

必须同时满足：

1. **离开本对话仍能看懂**（背景、结论、代码路径、如何运行）
2. **概念 → 为什么 → 怎么做 → 对应代码 → 坑**，缺一不可
3. **代码中的关键行能在笔记里对上号**（文件路径 + 符号名）
4. **计划当日的每个学习条目都有着落**：已讲 / 压缩合并进哪一节 / ⏭ 跳过
5. 含 **自测题**；压缩节奏下直接附简短参考答案（交互节奏可先留空答案）
6. 含 **互动与跳过记录**，避免下次把跳过当成已掌握
7. 中文正文；专有名词保留英文

禁止：

- 只有标题没有解释
- 大段粘贴聊天原文却不整理
- 笔记写了 A，仓库里实际代码是 B
- 用 `Foo`/`HelloWorld` 替换任务平台模型（Day 1 环境课除外）

## 配套代码质量（硬标准）

- 可编译、可运行；笔记里写命令和预期输出
- **教学注释必做**：见 [code-comments.md](code-comments.md)
  - 文件头标明 Day N + 钉死的概念 + 对照笔记章节
  - 入口类用分段注释把「计划条目 ↔ 代码块」对齐
  - 关键符号旁注写「为什么 / 和当日主题的关系」，禁止只复述代码
- 一个文件主攻有限概念，用类名/方法名把概念钉死（如 `ImportTask extends Task`）
- 压缩多日时仍然要能分别运行各日 Demo，不要互相踩 classpath
- 补注释或改逻辑后：若笔记导读与符号不一致，同步改笔记

## 与聊天的分工

- 对话：导读、路径、需要用户做的下一动作（若未压缩）
- 磁盘：完整教材。用户说「整理笔记」时以改 `学习笔记.md` 和代码为主，不要只在回复里重讲一遍却不改文件
