# 学习笔记模板

`dayN/学习笔记.md` 按此结构写。压缩时节可以变短，节不能缺。多日合并则每个 `dayN` 各用一份。

```markdown
# Day N 学习笔记：{主题}

- 日期：
- 计划：Week X Day N（章节）
- 节奏：标准 / 压缩 / 多日合并（本次还含 Day …） / 含跳过
- 本机环境：JDK / Maven（有变化才写）
- 学习包：本目录代码入口 `{入口文件}`
- 如何运行：
  `{命令}`
  预期输出：`{一行}`

## 0. 当日覆盖与跳过

| 计划条目 | 状态 | 落点 |
|---|---|---|
| Class / Object | 已学 | §1、Task.java |
| 故障实验 | ⏭ 跳过 | 未做 |

## 1. 概念（每个当日主题一小节）

### 1.x {名称}

- **是什么：**
- **为什么需要：** 不用会怎样
- **怎么做：** 3～8 行说清机制
- **代码：** `文件` / `符号` （引用真实路径）
- **坑：** 一条生产或排错相关

## 2. 代码导读

按文件说明职责，点出 3～8 个关键符号，不要贴全文件（源码在仓库里）。
源码须自带教学注释（见 `java-learn-notes/code-comments.md`）；本节与源码分段注释保持同一套概念名。

## 3. 与综合项目的关系

本周留在 dayN / 第几周接入 User Service 或 Task Service。

3. …

3. …

## 5. 故障清单（做了写过程；跳过则只列「建议日后做的 1 个实验」）

## 6. 互动与进度

| | |

闭环：✅ / ⏭ 列表。
```

篇幅：宁可写短而可执行，也不要空话。单日压缩建议控制在能一次读完（大约 150～400 行），靠代码文件承载细节，笔记负责索引和「为什么」。
