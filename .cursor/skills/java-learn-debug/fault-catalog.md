# 故障实验目录

按当前学习周选，每天只做 1 个。制造后必须走完：观察 → 分层判断 → 用户解释 → 修复/降级。

## 第 1 周：Java / 多线程

- Race Condition（多线程同时改任务状态）
- 可见性问题（未 `volatile` / 未同步导致读到旧值）
- 死锁（两个锁交叉获取）
- 线程池耗尽（队列堆满 + 拒绝策略）
- 未捕获异常导致线程静默退出

## 第 2 周：Spring Boot

- Bean 循环依赖
- 事务不生效（自调用、非 public、异常被吃掉）
- 全局异常处理漏网
- Validation 未生效
- 配置绑定失败（类型/前缀错误）

## 第 3 周：PostgreSQL / ORM

- DB Connection Timeout / 连接池耗尽
- 慢查询（缺索引）
- 事务里的 N+1
- 乐观锁冲突
- JPA / MyBatis 一级缓存或脏数据误解

## 第 4 周：Redis

- Redis 宕机或超时
- 缓存穿透
- 缓存击穿
- 缓存雪崩
- 分布式锁误删 / 未续期

## 第 5 周：MQ

- Broker 不可用
- 消息重复消费
- 消费失败未 ACK / 一直重试
- 死信队列
- 消息丢失（错误确认或错误持久化）

## 第 6 周：微服务

- 服务发现失败（Nacos 连不上）
- 配置中心拉不到配置
- 超时与重试放大故障
- RPC 序列化不兼容
- 网关路由错误

## 第 7～8 周：Docker / K8s / JVM

- 容器 OOMKilled
- Pod CrashLoopBackOff
- 健康检查失败
- G1 长时间停顿
- 堆外/堆内 OOM
- 线程 dump 看到死锁或线程池打满

## 通用观察清单

制造故障后优先看：

1. 应用日志里的异常栈和请求 ID
2. 是否只影响单个请求，还是整个服务不可用
3. CPU / 内存 / 线程数 / 连接数 / 队列长度
4. 依赖中间件是否可达
5. 修复后能否用同一输入复现「已恢复」
