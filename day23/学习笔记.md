## 1. 概念卡

| 名词 | 一句话 |
|---|---|
| `RedisTemplate<K,V>` | Spring Data Redis 的通用操作模板，Key/Value 序列化器可配 |
| `StringRedisTemplate` | 特化版：Key 和 Value 都是 String，轻量、免配序列化 |
| `RedisConnectionFactory` | 连接工厂（Lettuce 实现），管理连接池与线程安全 |
| `Jackson2JsonRedisSerializer` | 把对象序列化为 JSON 字符串，可读、跨语言 |
| `opsForValue()` | String 结构操作入口（set/get/incr/setIfAbsent…） |
| Cache-Aside | 读：先缓存后 DB；写：更新 DB 后删缓存（本日只搭缓存层） |

---

## 2. 为什么需要

Day22 用原生 Lettuce 客户端直接发命令，已经能跑通，但写业务代码时会有三个痛点：

1. **序列化样板多**：每次都要手动把对象转 JSON/byte[]，容易漏。
2. **类型不安全**：拿到 `Object` 还要强转，编译期发现不了错误。
3. **配置散落**：连接、超时、序列化器没有统一收口。

Spring Data Redis 用模板模式把这三件事封装掉，让业务代码只剩一句 `cache.put(user)`。

---

## 3. 原理与机制

### 3.1 模板类关系

```
RedisTemplate<K,V>  ←── 通用，需指定序列化器
StringRedisTemplate ←── extends RedisTemplate<String,String>，固定 String 序列化器
```

两者底层都走同一个 `RedisConnectionFactory`（默认 Lettuce），共享连接池。

### 3.2 序列化器选择

| 场景 | Key 序列化器 | Value 序列化器 | 理由 |
|---|---|---|---|
| 业务对象缓存 | StringRedisSerializer | Jackson2JsonRedisSerializer | Key 可读、Value 可读且跨语言 |
| 纯计数/锁 | 用 StringRedisTemplate | — | 不需要对象 |
| 性能极致 | StringRedisSerializer | JDK/Protobuf | 体积更小，但可读性差 |

**坑**：Spring Boot 默认给 `RedisTemplate<Object,Object>` 配 JDK 序列化，写进去是二进制乱码；生产务必显式改 JSON。

### 3.3 本次配置

`RedisConfig` 里显式声明了：

- 通用 `RedisTemplate<String, Object>`：Key 用 String，Value 用 Jackson JSON；
- 类型化 `RedisTemplate<String, User>`、`RedisTemplate<String, Task>`：注入即得泛型，避免强转。

## 5. 在 Spring Boot 中的典型用法

### 5.1 User Cache / Task Cache

已落成两个组件：

- `UserCache`：key 前缀 `user:`，TTL 300 秒；
- `TaskCache`：key 前缀 `task:`，TTL 120 秒。

业务层未来这样用（Cache-Aside）：

```java
public User getUser(Long id) {
    return userCache.get(id)
            .orElseGet(() -> {
                User u = userRepository.findById(id).orElseThrow();
                userCache.put(u);
                return u;
            });
}
```

> 写路径（更新 DB 后删缓存）以及击穿/雪崩/穿透，留到 Day24 专门讲。

### 5.2 StringRedisTemplate 场景

- **计数器**：`opsForValue().increment("pv:home")`，原子、无锁；
- **简易分布式锁**：`setIfAbsent(key, owner, ttl)` + Lua 脚本释放（本日只演示加锁）；
- **开关/令牌**：存 `"1"` 或 UUID，校验即删。

## 6. 常见错误与排查

| 现象 | 根因 | 处理 |
|---|---|---|
| 启动报 `Unable to connect to Redis` | Redis 没启动 / 端口不对 | 先 `docker exec redis22 redis-cli PING` |
| 写进去是 `\xAC\xED\x00\x05` 乱码 | 用了默认 JDK 序列化 | 显式配置 Jackson 序列化器 |
| 反序列化失败 `MismatchedInputException` | 类结构变了 / 无默认构造 | 加无参构造、保持字段兼容 |
| `incr` 返回 null | 连接闪断或事务中 | 判空并重试，或检查连接池 |
| 缓存与 DB 不一致 | 只更新了 DB 没删缓存 | Day24 讲写策略 |

## 7. 生产环境注意事项

1. **Key 规范**：统一前缀（如 `app:user:123`），方便按业务清理和监控。
2. **必设 TTL**：除非强需求，所有缓存 Key 都要 TTL，防止内存撑爆。
3. **大对象拆分**：超过 10KB 的 Value 考虑拆 Hash 或压缩。
4. **序列化版本**：Jackson 别乱升级，跨服务共用 Key 时字段变更要兼容。
5. **连接池**：Lettuce 默认共享连接，高并发下确认 `lettuce.pool` 配置。
6. **监控**：接入 Micrometer，看 `redis.commands` 延迟与命中率。
